# SWM 架构、进展与后续计划

日期：2026-09-13  
当前状态：**PARTIAL_DELIVERY，尚未完成软件交付**  
本文汇总用户确认的技术主线、已完成与未完成内容及最新抓放定位规则，不是新的实验成绩，也不授予真实设备权限。

## 一、总体主线

**SAM3D 建模与 FoundationPose 关键点同步 → SWM → 原子技能与基础工具 → 大模型任务程序 → 多假设仿真规划 → 执行与检查点验证 → 更新场景及物理参数 → 后续规划。**

复用现有共享定位服务、原规划器、原执行器及任务监督，不另建总体架构。目标不是单独完成抓笔程序，也不是积累离线测试。前期工作较多集中于 PushT 物理重放和规划审核，这部分已有实际结果，但整体框架尚未交付。

## 二、SWM：建模、非实时同步与物理参数优化

### 目标设计

- 新物体使用实际 SAM3D 建立三维模型；已有合格模型直接复用。
- SWM 保存物体名字、实例身份、三维模型、来源、尺度、位姿、功能性位姿及物理参数。
- 使用实际 FoundationPose 在关键检查点估计物体位姿，同步真实世界与私有仿真镜像，不要求实时视觉跟踪。
- 记录同一次实际动作的初态、工具运动、时间轴及动作后的物体变化。
- 在多个私有假设世界中，对同一动作、同一初态使用不同物理参数重放，将预测与实际变化比较，优化摩擦等参数。
- 更新后的参数必须由下一次正式规划消费，不能止于辨识报告。
- 无信息数据不强行收缩不确定性；全部模型失配不伪称校准成功；密度等参数不保证唯一可辨。

被观测世界只由实际执行或显式外部干预改变。镜像和假设世界可以按其职责初始化、同步或重置，但不能把预测位姿写回被观测世界冒充结果。

### 已完成

- SWM 的物体、模型、位姿、物理参数及来源记录结构。
- 同一帧供多个物体定位的共享采集接口。
- 实测动作记录、独立物理重放、参数比较及后验更新检查。
- 实际运行过同一主物理仿真实测动作的多参数 CPU PhysX 重放，以及另一动作的留出预测验证。
- 无信息、全部模型失配、证据身份不符等情况的拒绝更新机制。

### 未完成

- 本轮尚未实际跑通 SAM3D 新物体建模和 FoundationPose 完整模型链。
- 真实采集、参数辨识、下一次正式 worker 规划和执行的在线闭环尚未完成。
- 当前实际物理证据主要来自主仿真读回，不是真机实验。
- 已有多假设/并行接口，但重型原生实验主要按资源约束串行运行，不能宣称已完成并行加速验收。

## 三、原子技能与基础工具

### 目标设计

基于 SWM 向具身 Agent 提供抓取、放置、推、拉、旋转等原子技能，以及以下基础工具：

- 查询任意已注册物体的位置、姿态、来源、时间和有效性。
- 获取抓取、放置、推拉等功能性位姿。
- 调用原规划器计算到抓取或其他功能性位姿的路径。
- 查询技能实际可用性，以及绑定、原生仿真、模型和硬件验证状态。

未安装或未完成的技能保持不可用。不能包装整个旧任务冒充原子技能，也不能删除缺适配器检查来解锁能力。

### 已完成

- 位姿查询、功能性位姿查询及规划工具接口。
- 抓取、放置的原生阶段拆分，复用原协调器、规划器和共享执行边界。
- PushT 原生候选生成、原生 FK、多参数物理预测、碰撞审核及目标评分工厂。
- 通过现有多假设规划器实际运行两个不同候选、四组参数，完成八次新 CPU PhysX 预测和八次原生 GPU 审核，返回带阶段状态的原子计划。
- 工厂操作失败后关闭私有事务、清除半初始化候选并拒绝复用；六项生命周期定向测试通过。

这证明原生候选与物理预测进入了真实规划调用链，不只是读取旧评分表。但返回计划不等于获得执行授权，预测碰撞审核也不等于正式 runtime 的完整原子审核。

### 未完成

- 抓取、放置的正式 worker 闭环与全部对象验收尚未完成；笔的完整抓放仍受原碰撞门槛阻塞。
- Jimu 的完整原生任务接线与验收尚未完成。
- 拉、旋转尚未完成受约束场景的原生实现与验收。
- 工具接口存在，不代表每个物体已有可靠功能性位姿。
- 新工厂尚未安装为可执行在线 worker，实际原生取消验收仍未完成。

## 四、用户最新确认的抓放定位规则

**抓取前定位 → 按仿真计划完成抓取、搬运和放置 → 松爪并退让 → 再定位检查效果。**

- 夹爪夹住物体时，不要求抓后、放前的物体视觉重定位。
- 中间不增加物体跟踪，也不采用此前建议的“通过反馈持续跟踪被夹物体”作为新要求。
- 持物期间默认物体按仿真的抓持关系运动；它属于预测，不标记为真实定位，也不用于生成伪实测数据。
- 保留关节与夹爪执行反馈、碰撞检查和异常处理。这些不是物体视觉跟踪，也不能证明物体实际没有滑动。
- 放置、松爪、退让后的独立定位用于判断实际效果，不能用仍被夹持或遮挡时的检查替代。
- 定位发现偏差时，从实际状态重新规划剩余任务。例如笔已松开但放错位置，需要重新抓取，不能空手重放 place。

**实现状态：已完成首轮生产接线，包括成对抓放状态消费者、持物期间物体采集保护及隐藏闭爪后同步的替换；正式 worker 仍在原生候选规划阶段失败，完整抓放与释放退让后独立定位尚未验收通过。** 此前抓后/放前必须视觉定位，以及抓放六个检查点均须独立视觉采集的要求，应按本节调整。其余非视觉执行检查、碰撞要求和成功标准不随之取消。

## 五、大模型驱动的具身智能框架

### 目标流程

1. 大模型根据任务进行拆解，编写受限的技能调用程序。
2. 程序通过 SWM 工具查询对象、位姿、功能性位姿和技能能力，不直接访问 SDK 或执行任意代码。
3. 在私有仿真中对候选动作和物理参数进行多假设求解，找到可行路径。
4. 调用已审核原子技能，通过原有共享执行器执行。
5. 在允许的观测检查点比较预测与实际位姿，判断目标或场景是否变化。
6. 发生变化时更新 SWM，并对剩余任务重新规划；未知执行状态或控制故障不能盲目重试。

抓放按第四节执行，中间没有被夹物体实测，不能声称每个中间阶段都比较了真实物体误差。推、拉、旋转可在动作前后设置独立定位点，具体随原生技能实现验收。

始终区分命令完成、原子技能验证、任务目标达成和模型一致性。

### 已完成

- 受限任务程序、类型化技能请求、能力检查及部分恢复接口。
- 场景版本、计划绑定、过期计划拒绝和执行结果检查。
- 原生多假设规划器实际消费候选及物理预测，并选择原子计划。

### 未完成

- 尚未实际跑通“大模型生成程序 → 原子技能执行 → 观测结果 → 自动恢复”的完整链。
- 参数管理器到下一次正式 worker 规划尚未完全接通。
- 任务级偏差恢复、统一前端及耐久性验收尚未完成。

## 六、后续执行顺序

1. **修改抓放定位策略。** 取消持物期间强制视觉定位，明确预测状态与最终实测状态，不降低碰撞和执行检查要求。
2. **优先完成一个正式抓放 worker。** 从笔开始，贯通抓前定位、原生抓放、释放退让后定位、偏差处理及资源清理，不绕过当前碰撞失败。
3. **接通连续任务的物理参数闭环。** 同一实测动作重放得到的参数，由下一次正式规划实际消费，留下至少两次动作的关联证据。无信息时保留不确定性，不为演示强制更新。
4. **运行实际模型链。** 先用已有录制 RGB-D 和已有模型运行 FoundationPose；新物体再接实际 SAM3D、尺度校验与注册。设备、服务和下载权限遵守现有许可。
5. **补齐任务与五技能。** 推进 Jimu、推、受约束的拉和旋转，接入同一受限 Agent 程序及任务恢复流程。
6. **完成统一前端和发布验收。** 保留同一控制台、同一任务记录，按完整 G0–G10 提供实际证据；抓放观测策略按第四节新要求验收。

只有全部约定非硬件门槛通过后，才能标记 SOFTWARE_DELIVERY_READY，不能把剩余软件缺口统称为“只差硬件测试”。
