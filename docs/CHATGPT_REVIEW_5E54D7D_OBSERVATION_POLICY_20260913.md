# 5e54d7d 审阅：抓放观测窗口与交付主线收口

日期：2026-09-13。审阅基线：`5e54d7d014c088f6e47eb53471094d80efaaba1e`。
分支：`chatgpt/three-scene-software-closeout`。

这是对架构文档、关键执行/规划代码及已有验收记录的静态审阅，不是遍历全部170个历史提交的逐文件审计，也不是新的测试成绩。本轮不修改生产实现、不运行相机/机械臂/夹爪、GPU或商业模型。以下“应修改”均是后续实施要求，不表示已经修好。

## 1. 结论与需求优先级

总体三层主线没有必要推翻：SWM → 原子技能与工具 → Agent任务程序。现有原生场景、SE(3)基座转换、夹爪几何、阶段审核、实际物理重放等成果保留。

用户最新确认的抓放策略是：

> 抓取前定位 → 根据仿真计划执行抓取、搬运、放置 → 松爪并退让 → 再独立定位和验证。

持物期间不要求物体视觉重定位，也不增加通过反馈持续跟踪被夹物体的要求。关节/夹爪反馈、原碰撞与控制故障检查仍保留；持物物体的位置按仿真抓持关系预测，不宣称实际没有滑动。

`5e54d7d` 提交的是说明文档。其第四节正确承认“尚未修改代码”。旧Goal和滚动计划中的“每个原子前后独立视觉采集”“抓放六次视觉检查点”不能继续作为本模式的验收条件；应更新当前要求，保留历史实验原样。

当前仍是 PARTIAL_DELIVERY。新目标不是减少几次函数调用，而是把“原子执行边界”和“视觉观测边界”解耦。

## 2. P1：显式和隐藏的持物期间观测仍在主路径

### 确定的调用位置

- `swm/skills.py::AtomicSkillRuntime.run` 对每个技能无条件调用 `before_* / pre_execute_* / after_*`，并从后测物体位姿计算 `measured_T_tcp_object`。
- `swm/native_context.py::_build_pen_session` 给原生sink安装了 `MeasuredLiftAudit`。
- `swm/native_execution.py::execute_trajectory` 在闭爪后强制走该适配器。
- `swm/native_measured_lift.py::MeasuredLiftAudit.__call__` 调用 `sync('after_close_before_lift')`，从完整物体实测位姿更新抓持关系，再审计抬升。
- `swm/native_skills.py` 的place再次从物体 `measured` 字段取得相对TCP关系；抓取lookahead算出的放置路径当前会丢弃，注释仍要求place先新观测再求解。

因此，即使删除通常的 after_grasp/before_place，隐藏的闭爪后观测和后续数据依赖仍然存在。当前原生SIM读的是actor真值而不是FP；它在旧观测合同下合理，但新部署模式不能用actor真值替代已经取消的持物期间视觉输入。

### 最小收口方案

保留grasp/place两个原子及原阶段规划器，增加一个抓放组合操作的观测策略/执行上下文，不建立另一套任务框架：

1. 在目标尚未被夹持时取得可信场景，解析目标并形成完整抓放候选。规划过久或执行前场景已变，只能在仍未持物时重采集并重新规划；不能给旧图像换时间戳。
2. 保存选中的抓持关系、完整分段路径及其审核依据。阶段仍分别报告approach/grasp/lift/preplace/place/release/retreat。联合可行性已经接回，不要再次拆丢。
3. 持物期间使用已批准的模型抓持关系与原非视觉执行检查。允许为关节起点差异重新审计剩余路径，但不得引入新的真实物体位姿需求。预测不等于实测物体跟踪。
4. 原子grasp的指令完成与执行检查可以记录，物体结果标为 `visual_verification_pending` 或等价状态；在同一个已审计抓放上下文内，才允许进入配对place。
5. 松爪、完成退让、满足现有稳定/可见条件后重新定位；据此确认实际目标及更新SWM。放错但已释放时，重新生成抓取/调整任务，不空手重放place。

不能简单把grasp一律标为 `skill_verified=true`，也不能让所有依赖无条件跳过检查。反之，`integration._dispatch_session` 和 `program.run_program` 若仍只接受“每原子视觉成功”，新的合法待验证grasp就无法接place。状态消费者必须一起修改。

### 必须新增的验收

- 将物体定位接口设置为“持物区间调用即抛错”，完整抓放仍能走到松爪退让后的独立检测。
- 使用事件顺序断言最终采集开始晚于实际松爪和退让完成，不能仅验证调用总数。
- 整个持物区间不改写最后一次视觉观测的采集时间、序号或来源；最终实际偏差不是从预测自证。
- 执行故障/取消仍阻断后续动作，不自动松爪、回零或重放；已释放但落点错误进入重新抓取恢复。
- 任务级初始/最终观测可以保留；不把“必须恰好两次采集”硬编码成另一种过强限制，真正禁止的是持物区间新增物体定位依赖。

## 3. P1：SWM状态合同也要调整，不能只跳过sync

`scene.py::prepare_checkpoint` 仍要求全部对象具备新鲜、接受的实测位姿；`skills.py::_preconditions` 的place要求已验证持物，`native_tasks.measured_native_scene`只接受measured位姿。删同步而复用旧快照会产生两种坏结果：后续被陈旧状态检查拒绝，或为了跑通把预测伪装成新实测。

建议在既有SWM中分开以下信息，而不是修改measured字段的含义：

- `last_observed`：最后一次真实定位及其原始时间、来源、模型身份。
- `predicted`：由哪个已审核抓持关系、计划版本和执行阶段得到的模型状态，明确 `source=simulation_prediction`。
- `execution_state`：关节/夹爪反馈、当前阶段和已知/未知的执行结果。

字段名可沿用现有风格，关键是来源不可混淆。规划器可以在指定抓放操作内部使用预测态；物体目标的最终实测验证仍必须消费新定位。异常或中断后不能把这份预测直接作为另一个独立任务的新实测初态。

原生SIM的连续物体/接触读回可用于独立评估和保留的碰撞保护，但不得悄悄反馈“真实持物位姿”给规划器，使仿真享有部署时没有的信息。

另需明确SIM专属能力：`native_execution.py::_advance_feedback_closure`按指定actor的双指接触力控制闭爪。它不是视觉定位，但也不是已经有真机传感器依据的通用执行反馈。可以保留为明确标识的SIM策略；不能把它的可用性当作真实机器同样具备目标级接触力。迁移原完成版时应记录此策略与旧夹爪控制的差别。

## 4. P1：一个普通不可行候选可能中止整轮PushT搜索

静态代码可以确认以下路径：

`NativePushHypothesisFactory.operation`捕获任何BaseException后关闭整个factory；`_NativePushContext.evaluate`直接调用`audit_future_push`，只有完全通过才返回 `feasible=True`。后者在预测越界、关节超限或原碰撞审核拒绝时抛异常；`ParallelHypothesisPlanner.solve`使用pool.map收取结果，没有把正常候选拒绝转换为该候选的不可行结果。

因此，候选A在某参数世界下碰撞时，当前调用链可能直接使整个搜索失败，候选B即使安全也得不到正常评估。已有“所有候选均可行”的8次审核证据不能覆盖这个路径。本轮没有运行原生场景复现，不将其描述为已经发生的现场故障。

### 修复边界

- 已知候选不可行：使用专门类型或结构化结果，记录candidate、hypothesis、失败阶段和原因。该候选在任何必需假设下不合格就淘汰，继续评估其他候选。
- 真实错误：来源/身份不符、状态损坏、非有限数据、未知原生异常、超时和取消，继续按现有致命路径清理，不能吞错恢复。
- 不要通过捕获所有SceneInvalid来实现“继续”；同一个异常类现在混合了模型不匹配与候选碰撞，需要在知道语义的边界细分。
- 私有候选状态必须恢复或销毁后才尝试下一候选，不能复用受损的半初始化world。

验收至少包含“A拒绝、B可行→选择B”“A只在一组参数中碰撞→不能选择A”“全候选不可行→有界失败/任务等待”“身份损坏或取消→整体结束并清理”。拒绝碰撞候选，不等于解除碰撞保护。

## 5. P2：动态参照已部分实现，但Jimu尚未覆盖

`SkillRequest.target_reference_id/resolve`、完整SE(3)基座转换和原关系验证是本轮真正的改进。`native_tasks.CompiledNativeTask`当前却只为 `semantic_operator == 'inside'` 建立相对目标；其他atom仍使用原世界坐标。不能把容器目标的测试推广成两种底板装配目标都已随场景更新。

Jimu需要从可信结构编译器明确保留底板/连接面的参照，不能把所有support metadata自动视为同一种参考系：

- 抓取前已观测到底板变化：重编译同一设计的目标与剩余顺序，再规划。
- 持物区间：依新规则不声称能够实时发现底板或目标被移动。继续依赖批准的场景/抓持假设和执行保护；不为此重新增加视觉检查点。
- 放置后发现变化：更新实际底板和已放置件，判定当前结构与剩余任务，必要时重新抓取/恢复。不能只刷新源物体，却继续用旧槽位。
- 模型生成proof、12件库存、locked底板和父子支撑约束保持原验证，不能以动态目标为由放开任意模型写坐标。

这是Jimu完整迁移的未完成项，不是已部署的两个底板任务确定发生回归。

## 7. 偏离规划的主要风险是推进顺序，不是总框架换了

已做的几何、状态、碰撞、资源审核有价值。问题是很多工作仍停留在离线子系统、历史场景重放及单笔私有闭合预测，实际模型输入、用户可调用的抓放链、Jimu和上层恢复没有同步闭环。不要因为一个更细的物理一致性诊断还可增加，就让完整使用链继续停滞。

后续工作应按可验收功能推进：

1. 先实现第2、3节的新观测策略，在同一worker完成一个完整抓放和落点错误恢复。原规划与碰撞问题要继续修，不能只取消观测就认定动作可行。必要时按相同资产、场景、输入和明确夹爪策略对照旧完成版，找最早分叉。
2. 同步做已有录制RGB-D与已有物体模型的真实FoundationPose检查点测试，不等待所有摩擦辨识细节完成才接视觉；需要GPU时仍串行调度。RRTrack可复用，连续跟踪不成为本模式前提。
3. 修复第4节候选拒绝语义，然后将已有原T推段、观察、参数更新和下一次正式规划连接为至少两动作序列。不再只扩大离线参数排名表。物理拟合仍只用实际工具反馈与可观测时刻，持物预测绝不混入实测训练数据。
4. Jimu同设计在两种底板走新抓放观测窗口，接受最终实测结构验证；再推进完整Agent、拉/旋转和统一控制台。既有五技能范围保留，不靠列函数名完成交付。

正常抓放最好从同一已审核的联合计划按原子阶段执行；把视觉触发做成小型策略/组合上下文即可。不要为了新时机再写一套独立机器人、另一套SWM或新的前端。
